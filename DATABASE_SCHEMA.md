→ **User._id** (unique, required)- Bidirectional reference for easy navigation- Enforced via application logic and unique index### Employee → Employee (Self-Referencing)- **Employee.managerId** → **Employee._id**- Hierarchical reporting structure- Supports multi-level management### User → AuditLog (One-to-Many)- **AuditLog.performedBy** → **User._id**- **AuditLog.targetUser** → **User._id**- Tracks who performed actions and on whom### Employee → AuditLog (One-to-Many)- **AuditLog.targetEmployee** → **Employee._id**- Tracks employee-specific operations## Data Integrity Rules### User Collection1. **email** must be unique across all users2. **role** must be one of: administrator, manager, sales_executive3. **accountStatus** must be one of: active, inactive, suspended, terminated4. **employeeId** can only reference existing Employee documents5. **password** is automatically hashed before save6. **isActive** is automatically set based on accountStatus### Employee Collection1. **userId** must be unique and required (one-to-one with User)2. **employeeId** must be unique (company identifier)3. **department** must be one of predefined values4. **employmentStatus** must be one of: active, inactive, on-leave, terminated5. **managerId** must reference existing Employee document6. Email is NOT stored here (single source of truth: User)### AuditLog Collection1. **action** must be one of predefined enum values2. **performedBy** must reference existing User document3. **targetUser** must reference existing User document (if provided)4. **targetEmployee** must reference existing Employee document (if provided)5. **entityType** must match **entityId** reference type6. Logs are never deleted (compliance requirement)## Soft Delete Implementation### Employee Soft DeleteWhen an employee is "deleted":1. **Employee.employmentStatus** → `'terminated'`2. **User.isActive** → `false`3. **User.accountStatus** → `'terminated'`4. Both documents remain in database5. All references (Leads, Incentives, Analytics) remain intact6. Audit log entry created### User DeactivationWhen a user account is deactivated:1. **User.isActive** → `false`2. **User.accountStatus** → `'inactive'` or `'suspended'` or `'terminated'`3. User cannot login (checked in auth middleware)4. Employee record remains unchanged (if exists)## Transaction Boundaries### Create Employee (Transaction Required)```Session Start  → Create User  → Create Employee with userId  → Update User.employeeIdSession Commit```### Delete Employee (Transaction Required)```Session Start  → Update Employee.employmentStatus = 'terminated'  → Update User.isActive = false  → Update User.accountStatus = 'terminated'Session Commit```### Update Employee (Transaction Required)```Session Start  → Update Employee fields (job/location only)Session Commit```### Change User Password (No Transaction)```Update User.password (auto-hashed)Update User.changedPasswordAtAudit Log```### Change User Role (No Transaction)```Validate roleUpdate User.roleAudit Log```### Change User Email (No Transaction)```Validate email uniquenessUpdate User.emailAudit Log```## Index Strategy### Performance Optimization- **User.email**: Unique index for fast login lookups- **User.accountStatus**: Filter active/inactive users- **User.role**: Filter by role for RBAC- **Employee.userId**: Unique index for one-to-one relationship- **Employee.department**: Filter by department- **Employee.employmentStatus**: Filter active employees- **Employee.managerId**: Find direct reports- **AuditLog.createdAt**: Time-based queries- **AuditLog.performedBy + action**: User activity tracking- **AuditLog.targetUser**: User history tracking### Compound Indexes- **AuditLog**: (performedBy, action, createdAt) - User-specific action history- **AuditLog**: (entityType, entityId, createdAt) - Entity-specific history## Migration Notes### Existing Data- **Users without accountStatus**: Set to `'active'` if `isActive: true`, else `'inactive'`- **Employees without userId**: Link to User by email or name match- **Users without employeeId**: Link to Employee if match found- **Orphaned records**: Logged for manual review### Backward Compatibility- Existing Administrator account continues working- Existing authentication flow unchanged- Existing API responses unchanged (email populated from User)- Frontend requires no changes (virtual email property)
